# Project Status — Notes App

Audited 2026-10-11 by direct repository inspection (lock files, migrations, models, routes, components, logs) plus a full test-suite run. Behavior updated 2026-10-25 after folder management and email verification enforcement changes.

## Implemented & Verified

- **Auth (starter kit + Fortify v1.39.0):** registration, login, email verification, password reset/confirm, 2FA with confirm + recovery codes, passkeys. Covered by `tests/Feature/Auth/*` and `tests/Feature/Settings/*`.
- **Email verification enforcement:** `User` implements Laravel's `MustVerifyEmail` contract, so the existing `verified` route middleware now redirects unverified manual registrations. Fortify sends their verification email; Google OAuth accounts remain verified. Covered by auth and notes route tests.
- **Google OAuth (Socialite v5.31.0):** registration and login pages offer Google OAuth; `/auth/google/redirect` + `/callback` matches by `google_id`, falls back to email, links + verifies. Canceled or incomplete callbacks return to the originating login or registration page. Covered by `tests/Feature/Auth/GoogleControllerTest.php`. `google_id` is `#[Fillable]` (mass-assignable) and `#[Hidden]`.
- **Default folders:** `UserObserver::created` seeds Work/School/Personal/Projects; registered once via `User::observe()` in `AppServiceProvider::boot()`. Folder names now use a per user unique normalized key.
- **Notes (`Route::livewire('/notes', 'notes.index')`):** create/select/edit, folder filter + Trash, soft-delete/restore/force-delete, debounced live search (correctly parenthesized `LIKE` group), 4 sort orders, Tiptap rich-text editor. Covered by `tests/Feature/NotesTest.php`.
- **Quick capture (2026-10-29):** the header trigger (tooltip with `N`) and the mobile floating button open a Flux modal; the first line becomes the title (255 code point cap, overflow moves into the body), later lines become escaped `<p>` lines, CRLF and outer Unicode whitespace (including BOM) are normalized, and an empty capture stays open with inline feedback. Saves through the signed in user with `folder_id` null, resets the view to All Notes/Newest/empty search without disturbing the selected note or unsaved editor content, and reports a success or danger toast. The `N` listener guards fields, contenteditable regions, modifiers, key repeat, IME composition, open dialogs/popovers, and Trash. List previews now decode entities once before `strip_tags`, so escaped HTML reads as typed. Covered by 19 tests in `tests/Feature/QuickCaptureTest.php`; the keyboard, responsive, disabled control, and double submit checks remain for `/check verify`. Requires a frontend rebuild on the dev machine for the new Tailwind classes.
- **Note import and export:** the profile workflow exports and previews encrypted ZIP backups, validates archive structure and note HTML, stages previews for 15 minutes, and restores additively with duplicate reporting and attachment checks. Argon2id derives the encryption key and libsodium secretstream authenticates encrypted data chunks. The focused tests, full suite, and PHPStan pass. Beta browser verification remains open. The portable ID migration was applied to the current local SQLite app database on 2026-11-01; other environments still need to run it.
- **Save-button fix (2026-10-11):** the Save button called `getContent()` outside its Alpine `x-data` scope (`ReferenceError`, see `storage/logs/browser.log`). Fixed with the `save-note-requested` window-event pattern; no layout or server change.
- **Attachments:** validated upload (10 MB, explicit mimes) storing to `local` disk under `note-attachments/{userId}` + `NoteAttachment` row; selected-note list, owner-checked download, and delete UI. Canceling the native file picker clears any queued temporary upload, and inline upload validation errors fade after five seconds. Covered by `tests/Feature/NotesTest.php`.
- **Note reminders (2026-11-14):** one reminder per note, scheduled in UTC from the browser's local time and delivered as generic email to the owner's currently verified address with an owner-checked portable note link. Supports editing, clearing, bounded retries, generation-safe replacement, and defined Trash behavior. Reminder updates do not alter note timestamps or create sync records, and backup export or restore does not include reminder state. Covered by 24 tests in `tests/Feature/NoteReminderTest.php` and 4 JavaScript tests; the in-app mail transport check, queue worker retry timing, and browser verification remain open.
- **Frontend built:** `public/build/manifest.json` exists; Vite 8.3.0, Tailwind 4.3.3, Tiptap 3.31.3.
- **PHPStan level-7 typing fixes (2026-10-16):** resolved all 13 errors reported by `composer types:check` on the dev machine — explicit return types on both OAuth/attachment controller actions and PHPDoc relation generics (`BelongsTo<User, $this>`, `HasMany<Note, $this>`, …) on `Folder`/`Note`/`NoteAttachment`/`User`. Attachment download is typed `StreamedResponse` (verified against `FilesystemAdapter::download()` in vendor; `BinaryFileResponse` is wrong there). Full suite re-verified green after the change.
- **Editor click-to-focus fix (2026-10-16):** the Tiptap caret only appeared when clicking the text line, not the empty editor area. Cause: the `x-ref="editor"` wrapper carried `min-h-64 p-3`, but Tiptap's `.ProseMirror` contenteditable grows only to content height, so clicks in the empty area never reached ProseMirror. Fixed by moving `min-height: 16rem`, `padding: 0.75rem`, `outline: none` onto `.ProseMirror` in `resources/css/app.css` and reducing the wrapper to `w-full rounded-lg border` (`⚡index.blade.php:517`). Clicking anywhere in the box now places the caret (at doc end past the content). **Requires a frontend rebuild (`npm run dev`/`npm run build`) to take effect.**
- **Action feedback toasts (2026-10-16):** every note/attachment action now reports its outcome via `Flux::toast()` — success (`variant: 'success'`) for save, create, trash, restore, permanent delete, upload, and attachment delete; `variant: 'danger'` toasts on save/upload validation failure (inline `@error` messages are preserved by rethrowing the `ValidationException`). Renders through the existing `<flux:toast.group>` in the app layouts. Covered by 6 new tests in `tests/Feature/NotesTest.php` asserting the dispatched `toast-show` event, text, and variant (incl. that a failed save leaves the note unchanged).
- **Notes as the default destination (2026-10-25):** login, registration, two factor, password reset, and email verification now land on `/notes` through `config/fortify.php` `home`, and the Google callback keeps `intended()` so a deep link still wins over the default. The sidebar logo and its single nav item, the signed in call to action on the welcome page, the passkey fallback, and the profile resend verification default all point at `notes.index`. The dashboard route and view were kept, so `/dashboard` still renders and `DashboardTest` still covers it, it is simply unlinked. Covered by the updated assertions in `AuthenticationTest`, `RegistrationTest`, `EmailVerificationTest`, and `GoogleControllerTest`. The starter kit Repository and Documentation links and the empty Platform heading are gone from the sidebar, so Notes is the only nav item; the unused header layout was left untouched. The sidebar now collapses to an icon rail on desktop from its header toggle, keeps that state in local storage, and still behaves as a mobile drawer.

## Known Issues (ordered by severity)

1. ~~**`saveNote()` trusts `noteFolderId` without ownership check**~~ — **FIXED 2026-10-12.** `saveNote()` now validates `noteFolderId` with `Rule::exists('folders','id')->where('user_id', auth()->id())`; forged cross-user ids fail validation and the note is untouched. Covered by a regression test.
2. ~~**`saveNote()` has no title validation**~~ — **FIXED 2026-10-12.** `saveNote()` now validates `title` as `required|string|max:255`, with `@error` messages under the title and folder inputs. Covered by overlong/empty-title tests.
3. ~~**Pint style drift (5 files)**~~ — **FIXED 2026-10-12** (manual edits mirroring Pint's `laravel` preset: import ordering, unused imports, spacing/indentation; `pint --test` passes on all touched files). Notable corrections: same-namespace imports are *removed* by the preset (`User.php` needs no `Folder`/`Note` imports — `AGENTS.md` corrected), and the preset keeps `! $user` spaced. Verified by 26 passing tests across the 3 affected suites.
4. **Search `LIKE` does not escape `%`/`_`** — semantics only (searching `%` matches everything); the OR group scoping is correct, no leak.
5. **Git object damage — REPAIRED 2026-10-11.** Thirteen zero-byte loose objects (incl. tip commit `80cca0c`, mtime 2026-10-09) broke `log`/`status` (`fatal: bad object HEAD`). Healed by deleting the 0-byte files and copying the healthy objects from a fresh GitHub clone (`cp -rn`, content-addressed so existing valid objects were untouched). `git fsck --full` is now clean (only harmless dangling blobs); `log`/`status` work. Remote `main` was byte-identical to the local tip, so nothing was lost. Root cause undetermined — likely interrupted write or WSL filesystem flakiness (same family as the sandbox-only `storage/framework/views/livewire/*` I/O errors).
6. **Google OAuth callback has no throttle.** Acceptable while Google-verified emails only; revisit before broad exposure.
7. **Environment checks (updated 2026-10-24):** PHPStan and the frontend build both pass in this workspace. Browser preview of `/notes` redirects to login, so manual UI verification remains open. The current CLI upload limits are below the 100 MiB archive limit for note backups.
